[Download for Mac](https://github.com/JohnDeved/orbit-disk/releases/download/v0.9.10/Orbit-Disk.dmg). Open the disk image and drag Orbit Disk.app to Applications, or use **Orbit Disk → Check for Updates…**.

Orbit Disk 0.9.10 removes the write-backlog limits that could stall discovery on large maps, adds parallel folder discovery, and keeps discovered files available while saving continues.

## Faster discovery and live maps

- Up to four workers discover independent folders, each with its own enumeration buffer, secure directory cursor and cache reader.
- Discovery no longer pauses at the former 128 MiB pending-write budget, 4,096-directory frontier or 131,072-entry listing limit. Saving continues asynchronously.
- Browsing, search and collection read the live memory inventory without waiting for SQLite reads or writes. Discovered files remain visible after their save batches are retired, and eligible files can be dragged into collection and deleted while mapping continues.
- Navigating away retains mapping progress. Resumed maps reuse completed listings and discover unfinished folders; saved subtrees are shared between workers. Native and fallback enumeration both use the discovery workers. A busy or invalid shared cache falls back to filesystem discovery.
- Paged save queues avoid repeatedly shifting the remaining backlog. Metadata totals are computed in one pass, bounded previews select their largest children before creating rows, and change notifications replace preview polling. Saving alone no longer repeatedly rebuilds the live list and graph.
- Shared-cache readers no longer trigger unnecessary rescans when their SQLite journal connections open concurrently.
- Cached-listing readers release their SQLite snapshots between lookups so background cache checkpoints can progress.
- Cancelled mapping progress callbacks no longer retain discarded app models and their memory inventories. Outstanding preview searches cancel when their model is released, without publishing late results.

The live inventory grows with the files discovered. Memory pressure, filesystem latency and shared CPU or disk bandwidth can still affect speed. SQLite durability and deletion safeguards remain enabled. A crash preserves committed progress; unsaved observations can require rediscovery. Incremental refresh remains a separate path.

## Measurements

Three alternating pairs on warm local APFS fixtures measured discovery through the real resumable mapper, with database writing held stopped:

| Fixture and workload | Before, median | After, median |
|---|---:|---:|
| Flat, 60,008 records | 272.87 ms | 159.20 ms |
| Flat, with concurrent live previews | 219.81 ms | 199.76 ms |
| Nested, 90,068 records | 429.01 ms | 160.33 ms |
| Nested, with concurrent live previews | 420.88 ms | 195.37 ms |

The baseline is the earlier **unreleased memory-inventory implementation**, not 0.9.8. All 24 samples matched an independent filesystem inventory, including names, identities, logical sizes and hard-link allocation. These small warm samples exclude saving, publication and rendered frames; they do not predict cold or whole-Mac performance. Four workers use more CPU to reduce elapsed time. [Protocol and raw samples](https://github.com/JohnDeved/orbit-disk/blob/v0.9.10/docs/benchmarks/parallel-discovery.json).

A separate synthetic test held saving stopped: 0.9.8 stalled at 120,008 observations, while the backlog change completed all 160,008 in 95–113 ms. This verifies removal of write backpressure, not filesystem throughput. [Test method and results](https://github.com/JohnDeved/orbit-disk/blob/v0.9.10/docs/benchmarks/discovery-backlog.json).

## Deletion and navigation

- Fixed a completed map retaining an “Updating sizes” state after deletion. Completion now checks the saved removal cursor and session ownership, so an older completion cannot clear a newer deletion. Regular-file sizes remain visible while folder totals are repaired; surviving folders can still need incremental refresh.
- Drag folders from Finder onto the sidebar or main content to add persistent Places. Multiple folders are supported; duplicates and ordinary files are ignored. Removing a Place leaves the folder intact. Existing graph and list drags still add to collection.
- Added **Orbit Disk → Clear Cache…** beside Check for Updates. It restarts the app and removes saved maps and resumable mapping state. Files, Places and update preferences remain unchanged. The action is unavailable during file removal, and a failed reset can be retried before mapping starts.
- Removed welcome-screen slogans and repetitive helper text, keeping file status, actions and deletion consequences visible.

## Validation

Regression coverage includes discovery beyond the former queue limits, navigation and deletion before the first database write, four-worker reuse of nested saved folders, busy-cache fallback, cancellation, hard links, interrupted mapping and crash recovery. New checks cover Places persistence and cache-reset path validation. The release workflow runs the portable Linux checks and macOS regression suites before publishing the universal app and signed updater feed.
