Orbit Disk 0.9.7 reduces the work needed to discover files and keep their map on disk.

## Smaller, faster durable maps

- File records now store a parent ID and basename. Full paths are shared once per directory, and device/inode identities use integers. This removes repeated paths and staging metadata from the authoritative inventory.
- Hard-link ownership refers to node IDs. Folder navigation and bounded subtree cleanup use indexed directory paths, without rebuilding full paths for the entire map.
- The first listing batch remains available immediately. Later writes batch up to 1,024 records, with a cooperative 50 ms flush check between enumeration callbacks and a 16 MiB database page cache. These writer improvements were developed after 0.9.6 and are included here.
- Mapping still commits progress as it runs. Switching folders, reopening partial maps, sharing completed subtrees and deleting visible files during mapping retain their existing recovery checks. SQLite FULL synchronization is unchanged.

## Filename search

A disposable in-memory name index now filters search candidates from Orbit's existing inventory. It includes committed rows arriving during mapping, falls back to SQLite while it prepares, and preserves counts and global size ordering. It does not crawl the disk again or read file contents.

## Measured improvements

Five alternating fresh-process runs per version after warmup, on the same local APFS fixtures. Initial mapping includes filesystem enumeration, durable writes and final publication.

| Workload | 0.9.6 | 0.9.7 |
|---|---:|---:|
| Map 100,000 files in one folder | 6.95 s | 2.20 s |
| Saved inventory for those files | 121.0 MB | 20.3 MB |
| Load all 100,000 children from that saved map | 757 ms | 259 ms |
| Map 10,000 files across 1,000 folders | 1,282 ms | 1,040 ms |
| Refresh one 10-file branch in that map, including publication | 85.8 ms | 30.6 ms |
| Map 2,000 empty folders | 712 ms | 741 ms |

The first 128 entries in the large flat folder were readable at about 26 ms before and 31 ms after. Empty-folder traversal was effectively unchanged. The flat-folder process peaked at 145 MB versus 129 MB before, including loading every child; a smaller disk inventory does not imply lower peak app memory.

These are warm backend measurements, excluding rendered UI and optional search-cache preparation. Disk stalls varied, especially in the older version; this is not a whole-Mac or cold-storage speed guarantee. [Methods and full results](https://github.com/JohnDeved/orbit-disk/blob/v0.9.7/TECHNICAL-NOTES.md#compact-durable-inventory-097).

## Upgrading

Saved and unfinished maps from older versions rebuild once into inventory format 4. Subsequent launches resume the new format normally. The separate removal journal is preserved, including pending operations; it is not treated as a disposable cache.

## Validation

Regression checks cover interrupted listing commits and pruning, exact file identities and large sizes, hard-link accounting, incremental refresh, subtree reuse, cancellation, deletion races and Unicode saved-path lookup. The app also passes its release build and packaging checks. README screenshots update only after releases.
