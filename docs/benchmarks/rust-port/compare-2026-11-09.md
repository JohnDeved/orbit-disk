## Integrator notes (2026-11-09)
- **Load:** unrelated processes kept the load average at 9–13 during this run. The runs are interleaved, so the ratios hold up; absolute times are inflated.
- **Marking:** the suite's numbers (Rust 0.70–0.84×) disagree with direct runs of the same binaries. Run directly in alternating pairs (100k directories, 3 pairs × 3 passes), Rust took 0.091–0.104 s and Swift 0.091–0.108 s: parity. Both now use the same keyset algorithm and the work is I/O-bound. Wave C's 1.4–1.7× advantage was measured against a Swift run under heavier load. The `bench-compare` marking setup needs fixing before its numbers are used.
- **Discovery:** the mixed-deep comparison is unpaired (documented Swift 160 ms, Rust about 208 ms). Rust does not scale with workers on that shape: about 1.3 cores of kernel time, against Swift's documented 3.4. The paired real-file pipeline shows Rust discovery 1.5× faster. **Resolved, see `discovery-scaling.md`.** With a paired Swift probe on the same fixtures, Rust is 1.33–1.40× faster on mixed-deep and 1.18× on flat. Neither scales on this machine today: the kernel serializes directory opens (about 17.7 µs each) and per-file attribute reads system-wide, and Rust with one worker already reaches that floor. Swift's documented 160 ms did not reproduce; Swift measures about 265 ms here today.
